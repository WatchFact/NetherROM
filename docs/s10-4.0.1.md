# NetherROM 4.0.1 for the Galaxy S10 series

This branch starts directly at pristine ArtisanROM **4.0.1**, commit
`098409868245506be45824a793b41df69ccf15b6`. It imports the complete Galaxy S10
hardware layer from **3.1.0**, commit `4d30365b4452a651cc87af8e91733ec1c862f716`.
It does not descend from the earlier experimental NetherROM S10 branch.

| Device | Target | Models asserted by the original hardware source |
|---|---|---|
| S10e | beyond0lte | SM-G970F, SM-G970N |
| S10 | beyond1lte | SM-G973F, SM-G973N |
| S10+ | beyond2lte | SM-G975F, SM-G975N |
| S10 5G | beyondx | SM-G977B, SM-G977N |

The Snapdragon variants are excluded. These are original source compatibility
assertions, not claims that every listed SKU has been tested on hardware.

All 3.1.0 Exynos9820 modules are included: audio HALs, graphics/composer and
allocator, radio/RIL, Wi-Fi, input, vibrator, SNAP, camera APK/libraries/models,
MIDAS/PhotoRemaster, heart-rate service, Bixby key, extra dim, stock support
libraries and kernel integration. All four target overlays, feature settings,
camera modes and cutout animations are carried across. The original A26 and
r9s donor trees are restored, rather than substituting unrelated hardware
blobs to satisfy missing-file errors.

`scripts/s10/hardware-v3.1.0.json` records every original hardware source file.
`hardware-lock.json` checks every retained or migrated hardware input and
restored donor file by Git blob ID. Changes required by the 4.0.1 API are:

- Rename old configuration variables to the 4.0.1 names, preserving S10 facts.
- Move per-device camera XML into `target/<device>/camera/camera-feature.xml`,
  where the 4.0.1 camera module reads it.
- Preserve the 3.1.0 MIDAS model classification using structured JSON and the
  actual firmware device name, replacing an undefined shell variable.
- Apply version-sensitive camera/Bluetooth instruction patches only to unique
  matching binaries. An absent legacy signature remains an explicit runtime
  limitation; it does not become a successful functional test.
- Bring in the generic 4.0.1 multilib runtime and unencrypted-storage bridge.
  All SoC-specific HALs remain from the S10 hardware layer.
- Compile the original S10 kernel from pinned commit
  `9a0a792d227c8ae6cddac0c9d68a8bb9782c44cb`, with KernelSU disabled, then check
  each boot/DT image's format, device identity and checksum before importing it.
  Clang r547379 is pinned through Microsoft's AOSP mirror; its directory tree
  ID `a86cb6592a29d53254d3a88ff2d8282233a273e2` matches AOSP's toolchain.

## Clean Actions builds

`.github/workflows/s10-clean.yml` automatically builds all four targets on
this branch. Manual dispatch can select one target or all four. It uses no ROM,
firmware, patched APK or kernel cache. The assembler tools are restored from a
SHA256-pinned tool archive; each firmware download, kernel and ROM build starts
fresh. Successful preflight publishes a source-only prerelease. Flashable ROM
prereleases are published only after full assembly and package checks.

## Physical installation layout

S10 has physical `system`, `vendor`, `product` and `odm` partitions. Images use
ext4 and the legacy block OTA format, with no super image or dynamic partition
operations. The expected ArtisanROM repartition geometry is system 7000 MiB,
vendor 1500 MiB, product 1500 MiB and odm 4 MiB. The installer checks all OS and
kernel block capacities before writing any image. It does not repartition or
format userdata. The 3.1.0 kernel/vendor storage path expects unencrypted F2FS
userdata; changing the data filesystem requires matching kernel/vendor changes.

Package checks cover hardware inputs, kernel identity, expanded image sizes,
representative hardware files extracted from the actual ext4 images, physical
block installer structure and ZIP CRC. They do not establish bootability.
No physical S10 is attached to Actions. First boot, display, touch, camera,
recording, radio/IMS, Wi-Fi, Bluetooth, fingerprint, sensors, audio, storage and
suspend still require device testing and logs before any boot-verified release.

Upstream credits and GPL notices are preserved in the imported source files.
